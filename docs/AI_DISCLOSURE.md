# AI use disclosure

The brief permits AI tools with disclosure. This is the disclosure.

## What AI was used for

- Writing the pipeline code (`pipeline/`, `run_pipeline.py`, `tools/`): schema
  definitions, normalisation, the validator including cycle detection, the
  chunker, the exporter and the report generators.
- Retrieving the open-learning-resource listings and licence terms from NPTEL and
  MIT OpenCourseWare, and reading the nine NPTEL syllabus PDFs whose metadata
  appears in `resources.csv` as `tier=page_read`.
- Drafting this documentation, the schema rationale and the ideas note.
- Constructing the skill taxonomy and the course/resource-to-skill mappings.

## What AI was not used for, and why

**No course or academic-rule record was generated by a model.** The institute's
`robots.txt` disallows automated retrieval, so that data has to come from
documents a human opens. Rather than let a model produce plausible-looking course
codes, credit values and source URLs, those records are left uncollected and the
gap is stated in the README and in `SOURCES.md`. A source-traced knowledge base
whose sources were never opened is worse than a smaller one, and Part D invites a
reviewer to spot-check records against their sources — which only works if the
records are real.

**No embedding or LLM API is called anywhere in the pipeline.** The `token_estimate`
field is `len(text) / 4`, named as an estimate for that reason.

## Verification status

Every record is currently `verification_status=unverified`, meaning no human has
yet opened its source URL and confirmed it. The procedure for doing so is in
`DATA_QUALITY.md` §6. Rows marked `tier=page_read` in `source_note` had their
source document fetched and their metadata taken from it; rows marked
`tier=listing_only` are guaranteed only to have a correct title/URL pair, and
their `duration_value` is deliberately null rather than guessed.
